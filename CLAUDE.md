# CLAUDE.md: AI Воркбенч

Персональна PWA з агентами на Claude API (специфікація: `PWA-multitools.pdf`). Стек: Vite + React + TypeScript, Dexie, MiniSearch (етап 2), проксі на Vercel Functions (Node.js) + Upstash Redis.

## INVARIANTS (порушувати заборонено)

1. Ключ Anthropic існує лише в змінних середовища Vercel. У `src/` його немає і бути не може.
2. Проксі fail-closed: немає `APP_TOKEN`, `ANTHROPIC_API_KEY` чи Redis → запити відхиляються.
3. Проксі приймає лише моделі з `shared/pricing.ts` і `max_tokens` ≤ `MAX_OUTPUT_TOKENS`.
4. Service Worker ніколи не кешує `/api/*` (`navigateFallbackDenylist`, жодного `runtimeCaching` для API).
5. Конкретні назви моделей лише в `src/core/settings.ts` та `shared/pricing.ts`; агенти використовують `fast | balanced | deep`.
6. Користувацькі й зовнішні дані завжди в XML-тегах (`xml()` у `contextBuilder.ts`), ніколи не конкатенуються в інструкції.
7. Пам'ять змінюється тільки користувачем: форма на екрані «Пам'ять» або шторка «Запам'ятати» з підтвердженням. Агенти самі в пам'ять не пишуть (з етапу 3 лише `propose_memory` + черга підтвердження).
10. Поля профілю з `privateFields` ніколи не потрапляють у запит (`profileLines` у `contextBuilder.ts`).
12. Інструменти, що змінюють дані (`apply_edits`), показують diff і чекають підтвердження; відмова повертається моделі як `tool_result` з `is_error`. Створення нових даних (`save_artifact`) нічого не перезаписує.
13. Цикл tool use обмежений `MAX_STEPS` (12). Кожен інструмент реєструється в `src/tools/handlers.ts` з перевіркою входу через zod і описом для моделі.
14. Структурований вихід агентів = завершальний інструмент (`finalTool`) з валідацією zod в обробнику. Обмеження платформ і формат перевіряє код (`platforms.ts`), а не модель; автоповтор лише один.
15. Хмарна копія ніколи не відправляє порожній локальний стан, а `/api/backup` відхиляє порожню копію й зберігає попередню. Запуски в копію не входять.
16. Серверні інструменти: проксі дозволяє лише `web_search_20250305` з `max_uses` ≤ `MAX_WEB_SEARCHES`; найгірший випадок вартості (токени + пошуки) перевіряється до запиту.
17. Агент із веб-пошуком не пише в пам'ять напряму: лише `propose_memory` у чергу з позначкою `origin: web`. Вміст із інтернету й звіти пошуку передаються як `<untrusted_content>`.
11. Профіль, фрагмент і `upstream` не скорочуються бюджетом (`fixed`); скорочення завжди супроводжується попередженням на панелі контексту.
8. Дії зі змінами даних (перезапис, видалення, відправка) потребують підтвердження користувача.
9. CSP у `vercel.json`: `connect-src 'self'`. Не послаблювати без причини в `LESSONS.md`.

18. Claude Messages API: не відкидати й не спрощувати невідомі/службові content blocks у відповіді асистента. SSE-парсер має зберігати thinking-блоки та їхні `signature` (`thinking_delta`, `signature_delta`) для round-trip у наступних повідомленнях; tool-use JSON і citation blocks також зберігаються структурно. Не перетворювати thinking на звичайний текст і не синтезувати/підробляти підписи.
19. Сумісність параметрів перевіряється для конкретної моделі. Не додавати `temperature` без підтвердження, що вибрана модель його підтримує. Для структурованого виходу використовувати сумісний `tool_choice: auto`; обов'язковість `finalTool` перевіряє `runAgent` і повторює крок, якщо інструмент не викликано.

## Команди

- `npm run check`: typecheck + тести + збірка + димовий тест інтерфейсу (це і є DoD, показувати сирий вивід)
- `npm run dev`: `vercel dev` (потрібен `vercel env pull .env.local`)
- `npm run dev:ui`: лише Vite, `/api` проксюється на `API_ORIGIN` (за замовчуванням `localhost:3000`)

## Дизайн

Холодний папір + темно-синій `#1F3864` + сигнальний жовтий `#F2C230`. Лінійка-індикатор (`.gauge`) для довжини, токенів і витрат; світла й темна теми через змінні в `src/styles.css`. Тексти відповідей шрифтом із засічками, інтерфейс системним.
