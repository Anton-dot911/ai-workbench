# AI Воркбенч (етапи 1–3a: каркас, контекст, цикл агента)

Персональна PWA з агентами на Claude API. Етап 1: проксі з лімітом витрат на Vercel, встановлюваний застосунок (PWA), сховище Dexie, стрімінг відповіді, агент «Документи».
Етап 2: профіль, пам'ять, пошук BM25, збирач контексту з бюджетом токенів і панель контексту.
Етап 3a: цикл tool use, правки з diff і підтвердженням, реєстр агентів, шторка агентів і slash-команди.

```
Браузер (PWA, IndexedDB) ──HTTPS──► /api/claude (Vercel Function) ──► api.anthropic.com
                                     токен · білий список моделей · ліміти витрат (Upstash Redis)
```

## Розгортання (достатньо телефона)

1. Створіть репозиторій на GitHub і залийте вміст архіву (разом із `package-lock.json`).
2. Vercel → **Add New → Project** → імпорт репозиторію. Framework визначиться як Vite.
3. У проєкті: **Storage → Marketplace → Upstash Redis** → підключіть до проєкту. Інтеграція сама додасть змінні `KV_REST_API_URL` і `KV_REST_API_TOKEN` (або `UPSTASH_REDIS_REST_*`). Підтримуються обидва варіанти.
4. **Settings → Environment Variables** (для Production і Preview): `ANTHROPIC_API_KEY`, `APP_TOKEN` (довгий випадковий рядок), `DAILY_LIMIT_USD`, `MONTHLY_LIMIT_USD`. Повний список у `.env.example`.
5. **Redeploy**, відкрийте адресу проєкту, введіть `APP_TOKEN`.
6. Safari → «Поділитися» → «На початковий екран». Застосунок запуститься як окремий PWA.

Без Redis або без `APP_TOKEN` проксі **відмовляє у всіх запитах** (так задумано: без лічильника витрат ліміт не працює).

## Що де лежить

| Шлях | Призначення |
|---|---|
| `api/claude.ts` | Проксі: токен, білий список моделей, ліміт `max_tokens`, денний і місячний ліміти, облік витрат зі стріму |
| `api/_lib/` | Автентифікація, сховище лічильника, розбір usage зі стріму |
| `shared/pricing.ts` | Ціни й `costUsd` (спільні для проксі та клієнта) |
| `src/core/` | Клієнт API (fetch + SSE), `contextBuilder` (джерела, бюджет, пріоритети), `retrieval` (BM25), `session` (спільний стан екранів), `runAgent` |
| `src/agents/` | Маніфести агентів і реєстр (`registry.ts`: список, slash-команди) |
| `src/tools/` | Інструменти агентів (`handlers.ts`), рушій правок (`edits.ts`), типи |
| `src/db/` | Схема Dexie, збереження артефактів, експорт |
| `src/screens/`, `src/ui/` | Екрани: Робота, Контекст, Бібліотека, Пам'ять, Налаштування, вхід; шторки й форми |
| `scripts/ui-smoke.cjs` | Димовий тест зібраного інтерфейсу в jsdom |

## Моделі та ціни

Конкретні моделі згадуються лише в `src/core/settings.ts` (`MODEL_MAP`) і в таблиці цін `shared/pricing.ts`. Проксі приймає тільки моделі з цієї таблиці. Ціни взято з документації Anthropic станом на жовтень 2026 (Haiku 5.5: $0,10/$0,50, Sonnet 5.5: $2/$10, Opus 5.5: $4/$20 за 1 млн токенів). Звіряйте їх із [сторінкою цін](https://platform.claude.com/docs/en/about-claude/pricing); якщо змінилися, задайте `PRICES_JSON` у Vercel без перебирання коду. Ціна читання кешу Sonnet 5.5 у джерелах розходиться ($0,20 → $0,10 після зниження), у коді стоїть $0,10.

## Як працює контекст (етап 2)

Кожне джерело (профіль, закріплені факти, пам'ять, споріднені документи, фрагмент, історія) це рядок на екрані «Контекст» з перемикачем, токенами й переглядом того, що піде в запит.

| Рівень | Джерела | Як потрапляє в запит |
|---|---|---|
| Постійний | профіль, закріплені факти | у системний префікс, що кешується |
| Релевантний | пам'ять, документи за темою задачі | пошук BM25 по тексту задачі, топ-K |
| Оперативний | фрагмент, історія сесії | напряму |

Бюджет токенів залежить від рівня моделі (`CONTEXT_BUDGET`). Профіль і фрагмент **не скорочуються**; решту скорочують за пріоритетом: спершу відкидаються останні елементи (в історії найстарші), потім середина тексту, потім усе джерело. Про скорочення панель попереджає. Історія сесії вимкнена за замовчуванням (вмикається перемикачем).

Пошук українською працює без ембедингів: слова обрізаються до 6 літер (документи, документів, документами → «докуме»), плюс префіксний і нечіткий збіг. Для ваших обсягів (сотні записів) цього вистачає; ембединги додамо, коли записів стане понад 1–2 тисячі.

Пам'ять змінюється лише вами: факти додаються вручну або кнопкою «Запам'ятати» під відповіддю (з редагуванням і підтвердженням). Поля профілю можна позначити «приховано»: вони не потрапляють у запити.

## Агенти й інструменти (етап 3a)

`runAgent` виконує цикл tool use: модель викликає інструменти, застосунок виконує їх і повертає результат, доки модель не дасть відповідь без виклику. Запобіжник: не більше 12 кроків за запуск. Усі кроки одного запуску тарифікуються й підсумовуються в журналі (`steps`, `toolCalls`).

| Інструмент | Що робить | Підтвердження |
|---|---|---|
| `search_context` | шукає в пам'яті й бібліотеці (BM25) | ні |
| `read_artifact` | читає артефакт частинами (`offset`, `limit`) | ні |
| `apply_edits` | точкові правки {find, replace} або {insertAfter, text} у фрагменті чи артефакті | **так, diff** |
| `save_artifact` | створює новий артефакт (існуючі не перезаписує) | ні |
| `ask_user` | питання користувачу з варіантами | відповідь користувача |

`apply_edits` показує diff: кожну правку можна прийняти або зняти. Правка, чий фрагмент не знайдено або він неоднозначний, не застосовується, а модель отримує причину й може виправитись. Зміна артефакту створює нову версію (стара лишається, на екрані «Бібліотека» є відкат). Відхилення повертається моделі як помилка інструмента.

Агента вибирають тапом по заголовку на екрані «Робота» або командою на початку задачі (`/док`). Новий агент це маніфест у `src/agents/registry.ts`.

## Відомі обмеження

- Поки один агент («Документи»); «Перевірка» й «Пости» у 3b, «Пошук» і черга підтвердження пам'яті у 3c.
- Кожен крок циклу повторно надсилає контекст: префікс кешується, але довгі цикли дорожчі за один виклик.
- Історія сесії живе в пам'яті сторінки й губиться при перезавантаженні.
- Мітка кешу діє, лише якщо префікс (інструкції + профіль + закріплені факти) перевищує мінімальний розмір кешу моделі (≈1024 токени). Для короткого профілю кешу не буде, це нормально.
- Запуск без мережі показує помилку, черги запитів ще немає (етап 7). Оболонка й бібліотека працюють офлайн.
- Вартість у застосунку це оцінка з `usage`; авторитетний лічильник тільки на проксі.
- Токен доступу лежить у `localStorage`; захист від викрадення скриптами дає суворий CSP (`vercel.json`).

## Відхилення від специфікації

- **Node.js замість Edge.** Vercel позначив Edge Functions застарілими; проксі це звичайна функція Node.js з Web Handler (`export function POST(request)`).
- **Власний fetch + SSE замість `@anthropic-ai/sdk`.** Для етапу 1 це менше коду і простіший шлях `/api/claude`. SDK підключимо на етапі 3 разом із tool use, якщо знадобиться `finalMessage()`.
- **`pinned` у пам'яті це `0 | 1`.** IndexedDB не індексує boolean, тому запит `where("pinned").equals(1)` зі специфікації з `boolean` не спрацював би.
- **Підпис вкладки «Параметри».** П'ять вкладок на 375 pt не вміщують слово «Налаштування» (назва екрана лишилась повною).
- **401 для невірного токена** (замість 403), щоб клієнт відрізняв «вийти» від інших помилок.
